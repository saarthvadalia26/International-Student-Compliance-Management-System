## Overview
This document structures risk identification to prevent codebase regressions and resource mismatches.

## Detailed Guidance
*   **Risk Management Protocol**:
    *   **Identification**: Engineers must register risks during the planning phase of each sprint.
    *   **Assessment Criteria**: Evaluate risks based on likelihood (1-5) and impact (1-5) to calculate severity scores.
    *   **Mitigation Actions**: High-severity risks require a written mitigation plan before sprint kickoff.
    *   **Escalation Path**: Unmitigated high risks must be escalated to the Project Governance Board.

## Best Practices
*   Update the project risk register weekly.
*   Document technical debt as code risks in the register.

## Examples
*   Risk: "WhatsApp API downtime" -> Severity: High -> Mitigation: Implement email backup channel.
