# ISCMS v0.2.0 Release Notes

This document details all completed features, database migrations, security enhancements, and verification suites for **ISCMS v0.2.0**.

> [!NOTE]
> `v0.2.0` represents the second major milestone release of ISCMS, featuring academic program integrity, dynamic application URL resolution, graduation reminder boundary enforcement, direct student portal authentication, and ISO phone code standardization.

---

## 1. Compliance Reminder Boundary — Graduation Date Enforcement
- **Graduation Boundary Rule**: The automated reminder engine and dispatch pipeline now strictly enforce that no expiry reminders are calculated, queued, or dispatched when `document_expiry_date > student_graduation_date` (`student_academic.expected_graduation`).
- **Independent Document Evaluation**: Evaluated independently per document (Passport, Visa, eFRRO). A student with a passport valid beyond graduation has their passport schedule marked inactive, while visa and eFRRO remain active if expiring before graduation.
- **Missing Graduation Date Handling**: When `expected_graduation` is missing or null, reminders are evaluated dynamically on document expiry dates without assuming ineligibility; UI displays a pending boundary indicator.
- **Scheduler & Queue Re-evaluation**: `ReminderSchedulerServer` cancels and supersedes previously queued notifications for documents that expire after expected graduation.
- **Dispatch Action Blocking**: Server action manual dispatch triggers (`triggerReminderDispatchAction`) prevent dispatch and return `after_graduation` status with clear error messages.
- **UI/UX Schedule Status**: `DocumentReminderSchedule` displays document-themed inactive schedule banners (Passport: blue, Visa: purple, eFRRO: gold/amber) with clear explanatory text when a document expires after graduation.

---

## 2. Student Portal — Direct Identifier Authentication & Reversible OTP
- **Direct Single-Step Login**: Students can log in directly using either their **University Enrollment Number** (e.g. `NFSU/2026/001`) or active **Passport Number** (e.g. `UK78945612`).
- **Session Architecture**: Authenticates via Supabase Auth and establishes full session context.
- **Zero Mock / Full Security**: Enforces unique record matches, blocks duplicate/ambiguous identifiers with generic messages without exposing student records, and blocks disabled/suspended/archived student profiles.
- **Reversible OTP Architecture**: Feature flag `STUDENT_PORTAL_OTP_ENABLED` / `STUDENT_PORTAL_AUTH_MODE` in `src/config/feature-flags.ts` preserves the complete 6-digit WhatsApp OTP architecture for instant reactivation when WhatsApp Business API is ready.
- **Clean UI**: Removed OTP input boxes and claims of WhatsApp verification from the student login page in direct identifier mode.

---

## 3. International Phone Numbers & E.164 Dial Code Architecture
- **ISO Master Reference Data**: Added `phone_code` international dial codes (e.g. India `+91`, Fiji `+679`, USA `+1`, UK `+44`, Australia `+61`, etc.) across all 120+ ISO 3166-1 country records in `public.countries` and `src/domain/countries/iso-countries.data.ts`.
- **Database Schema**: Migration `049_v020_phone_numbers_and_reminder_boundary.sql` added structured phone columns (`phone_local_country_code`, `phone_local_number`, `phone_home_country_code`, `phone_home_number`) to `public.student_contact` with safe backfill.
- **Reusable `PhoneInput` Component**: Created `src/components/ui/phone-input.tsx` with country flag, dial code selector, searchable country list, and phone number input.
- **E.164 Normalization**: Compatible with WhatsApp E.164 phone formatting (`formatE164Phone`).
- **Form Integration**: Integrated into `Add Student` (`src/app/(app)/students/add/page.tsx`) and student contact repository pipelines.
- **Excel Bulk Import**: Extended `BulkStudentImportService` to support both composite international numbers (`+679 1234567`) and separate country code + number columns with full backward compatibility.

---

## 4. Academic Program & Course Name Integrity
- **Database Schema**: Migration `050_academic_program_integrity.sql` seeded 16 canonical programs with degree levels (`UG`, `PG`, `INTEGRATED`, `PhD`, `Diploma`), duration, and foreign keys.
- **Searchable Program Selector**: Built `SearchableProgramSelector` combobox with live filtering across name, code, level, and school.
- **Form & Import Integration**: Unified across Add Student, Edit Student, Bulk Import, Reports, and Student Portal.

---

## 5. Single Source of Truth Application Version Architecture
- **Canonical Version**: Root `package.json` contains `"version": "0.2.0"`.
- **Centralized Version Module**: `src/config/version.ts` exports `APP_VERSION` (`"0.2.0"`) and idempotent formatter `getDisplayAppVersion()` (`"v0.2.0"`).
- **Diagnostics & UI**: Integrated across Branding, System Diagnostics, Settings, and Health Dashboard.

---

## 6. Dynamic Request Origin & Canonical App URL Resolution
- **Environment-Aware Base URL**: `src/config/app-url.ts` inspects dynamic request headers (`x-forwarded-host`, `host`, `x-forwarded-proto`), `VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_URL`, and `NEXT_PUBLIC_APP_URL`.
- **Zero Localhost Leakage**: Completely prevents student portal magiclinks and auth callbacks from redirecting to `localhost` in deployed preview and production environments.

---

- `050_academic_program_integrity.sql`: Canonical NFSU academic programs and degree level catalog.
